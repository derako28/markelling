# /daily — черновики дня

Работает и интерактивно, и через `claude -p`. **Вопросов не задавать**: чего не хватает — в раздел
«Нужно от Полины» итогового файла, и идти дальше. Аргумент `no-commit` — всё сделать, но не коммитить.

## 1. Дата и состояние

- `node scripts/now.mjs` → `date`, `dateCompact`, время по Варшаве.
- Итоговый файл: `drafts/<date>.md`. Если уже есть — не затирать: дописать новый блок
  «Прогон HH:MM» с продолжением нумерации id.
- Прочитать `brief.md`, `playbook.md`, `experiments.md` (раздел «Активный»).
- Определить **текущий вариант эксперимента** на сегодня:
  - эксперимент по времени — вариант задаёт предложенное время публикации; распределить так, чтобы к концу
    эксперимента у каждого варианта было 5–6 постов (посчитать, сколько уже вышло, по прошлым `drafts/` и `my_posts`);
  - эксперимент по первой строке или формату — чередовать варианты, отдавая приоритет тому, где постов меньше;
  - эксперимент ещё не начался — так и написать, вариант «до старта».
- Серии и планы из `brief.md` (например, серия из 5 постов) — если серия идёт, одна из тем дня — следующий
  пост серии.

## 2. Материал из Twitter Factory

Сначала `health` (. Потом, не останавливаясь на ошибках:
- `rising_posts` (hours: 48, limit: 15) — что растёт сейчас;
- `pushed_topics` (hours: 48) — что толкает алгоритм у маленьких аккаунтов;
- `top_posts` (workspace: "finance", days: 2, sort_by: "views", limit: 20);
- `hooks` (workspace: "finance", days: 14, limit: 20);
- `niche_people` (workspace: "finance", days: 2);
- `my_posts` (days: 30, limit: 100) — чтобы не повторяться.

Инструмент упал — записать в «Нужно от Полины»: какой и с какой ошибкой. Материала нет совсем — взять
темы из серий `brief.md` и из своих лучших постов (новый герой в той же рамке).

## 3. Три темы

Выбрать 3 темы, которые:
- подходят под `brief.md` (темы, аудитория, табу — табу не предлагать никогда);
- не повторяют свои посты за 30 дней (герой, история, первая строка);
- дают применить текущий вариант эксперимента;
- имеют источник: пост ниши (ссылка), хук из библиотеки, серия, или своя идея (так и пометить).

## 4. Автор → критик

Для каждой темы:
1. Агент `author`: тема, источник, вариант эксперимента, предложенное время. Получить 2–3 варианта.
2. Агент `critic`: передать **только** тексты вариантов, тему и вариант эксперимента. Рассуждения автора
   и строку «Применённые правила» не передавать.
3. Если у лучшего варианта меньше 7 — вернуть автору замечания критика, получить переписанные варианты
   и оценить ещё раз. **Не больше одного круга.** Если всё равно ниже 7 — оставить как есть с пометкой.

Темы можно обрабатывать параллельно.

## 5. Итоговый файл `drafts/<date>.md`

```
# Черновики — <date> (<день недели>)

Эксперимент: <название>, вариант(ы) дня: …
Сгенерировано: <время Варшава>

## D-<dateCompact>-1 — <тема>
- Источник: <ссылка на пост / хук / серия / своя идея>
- Вариант эксперимента: …
- Предложенное время: <Пн 14:00 Варшава>
- Оценка критика: <лучший вариант N — X/10; остальные …>

### Вариант 1
<текст>

### Вариант 2
<текст>

### Замечания критика
- Вариант 1 — X/10: …
- Вариант 2 — X/10: …

### Проверить
- <факт> — <источник>

## D-<dateCompact>-2 — …

## Нужно от Полины
- <чего не хватило: видео, решение, упавший инструмент> или «—»
```

Тексты вариантов — после переписывания, если оно было. В «Замечаниях» — итоговые оценки.

## 6. Коммит

Если не `no-commit`:

```
git add drafts/<date>.md
git commit -m "daily: черновики <date>"
```

Только этот файл. Не пушить. В конце напечатать короткую сводку: темы, оценки, «Нужно от Полины».
